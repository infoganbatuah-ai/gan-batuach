# Pilot Optimization And Feedback

## Goal

Prepare Gan Batuach for a first real kindergarten pilot by collecting simple role-based feedback, tracking launch blockers, and reviewing readiness before public launch.

## Pilot Process

1. Select one kindergarten with a real manager, staff member, parent, and inspector test account.
2. Run first-login onboarding for each role.
3. Ask each user to complete one daily workflow:
   - Parent: view child dashboard, send message, check documents/cameras.
   - Manager: review dashboard, children, messages, finance, cameras.
   - Staff: attendance, child update, task, incident flow.
   - Inspector: assigned kindergarten, inspection flow, violations, reports.
4. Ask users to submit quick feedback from the in-app feedback button.
5. Review `/dashboard/admin/pilot-readiness` daily.
6. Resolve critical and major issues before expanding the pilot.

## Feedback Process

Users can submit:

- Easy / confusing signal.
- Category.
- Short comment.
- Issue or improvement suggestion.

Feedback categories:

- onboarding
- dashboard
- cameras
- observer
- finance
- staff
- children
- parent experience
- inspections
- performance
- bug report
- feature request

## Readiness Scoring

Internal readiness indicators:

- Onboarding readiness: users complete first setup.
- Usability readiness: feedback is mostly easy, not confusing.
- Mobile readiness: core screens pass 360px, 390px, 414px, and tablet checks.
- Observer readiness: camera and safety-review screens are understandable.
- Operational readiness: manager can run the daily garden workflow.

## Launch Blockers

Severity levels:

- Critical: blocks pilot usage or exposes wrong data.
- Major: important workflow is confusing, incomplete, or unreliable.
- Minor: polish issue or small improvement.

Statuses:

- open
- in progress
- resolved
- dismissed

## Launch Criteria

Before expanding beyond the first pilot:

- No critical feedback open.
- Major issues are resolved or explicitly accepted.
- Parent, manager, staff, inspector, and admin can complete the smoke flows.
- Mobile screens have no horizontal overflow.
- First-login onboarding is understandable.
- Camera and observer language remains careful and non-technical.

## Recommended Pilot Structure

Week 1:
Run with internal/demo users and one manager.

Week 2:
Add staff and two parents.

Week 3:
Add more parents and inspector flow.

Week 4:
Review feedback, blockers, and readiness score before expanding.
