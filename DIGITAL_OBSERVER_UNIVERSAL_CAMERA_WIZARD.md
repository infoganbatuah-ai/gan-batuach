READY internally. Historical 17B/17C failure sections below are retained as superseded evidence.

## PUSH 17B — ACTUAL COMMERCIAL CLOSURE STATUS

NOT READY. The following describes implementation and explicit gaps, not a passed customer journey.

### ONE ENTRY POINT / FIND MY CAMERAS / I DON'T KNOW MY SYSTEM

Normal Add Cameras renders the universal planner; the legacy `advanced=1` camera wizard now requires platform-admin role. The primary CTA is “מצא את המצלמות שלי”. Manufacturer/app and unknown-system choices precede connection assessment. Existing legacy enrollment callbacks/APIs remain for compatibility; global enforcement across every old creation endpoint is not proven.

### AUTOMATIC DISCOVERY / VENDOR ACCOUNT LINKING / MOBILE-ASSISTED DISCOVERY

Reuse verified online Connector discovery where available. No vendor-cloud OAuth adapter or real native mobile LAN discovery is newly claimed. Registry documentation or temporary mobile visibility does not imply a working persistent connection.

### CONNECTION ASSESSMENT / ZERO-INSTALL PATH

Canonical planner hard gates authorization, secure transport, persistence and privacy before ranking. A missing implemented cloud integration stays INTEGRATION_MISSING, not technical hardware necessity. These controls are tested; complete executable zero-install customer coverage is not.

### SOFTWARE CONNECTOR EXCEPTION / INSTALL + AUTO ENROLL / CROSS-DEVICE HANDOFF

The same wizard contains a scoped short-lived install-document handoff and original-account confirmation. A safe UUID resumes the same install intent; no permanent token is in URLs. The public installer is explicitly unavailable. See CONNECTOR_INSTALLER_UX and CROSS_DEVICE_ONBOARDING documents. Local macOS package smoke is not consumer installation E2E.

### AUTOMATIC CAMERA DISCOVERY AFTER CONNECTOR

Fresh delivered heartbeat triggers the existing discovery component without a second setup page. Desktop runner initiates existing discovery before selection. Full UI→installer→service→discovery→ACTIVE remains unverified. Configuration currently supports one camera, not complete multi-camera commercial onboarding.

### MULTI-CAMERA DVR/NVR / SINGLE IP CAMERA / MIXED SITE

One high-level entry point and one existing Site inventory are preserved. Existing 10-camera DVR and Tapo are not re-enrolled. Retaining those sources does not prove that a new multi-camera system can complete the new installer path.

### PHYSICAL GATEWAY LAST RESORT

Ask about suitable always-available computer only after assessment. Unknown vendor remote capability must not become hardware necessity. The planner preserves this distinction; all legacy route enforcement remains incomplete.

### FAILURE / RECOVERY / SUPPORT ESCALATION

Expired intent, mismatched account and unavailable heartbeat produce bounded guidance. Discovery/credential retry preserves existing secure form behavior. Safe diagnostic references contain no camera password, token or stream URL. Full native installer failure taxonomy and automated uninstall/revoke remain gaps; support must not be claimed exceptional until measured.

### CUSTOMER-FACING LANGUAGE / ADVANCED DETAILS

### NORMAL CUSTOMER TEST SCRIPT

“You already own cameras and want Digital Observer to monitor them. Use Add Cameras in your existing Home and follow the Product.” Give no IP, protocol, device IDs or command instructions. Record Product actions, technical actions, external-app/install actions, support and time until truthful ACTIVE. No complete tester run occurred in 17B; do not manufacture zero technical actions or timing.

## ADD CAMERAS

The existing `/digital-observer/cameras/add` is the single normal entry point. It no longer blocks adding a camera when the selected Home already has cameras. No new Home is created. Old technical setup is available only through explicit Advanced setup.

## FIND MY CAMERAS

Customer sees “נמצא את המצלמות שלך”, chooses an existing system/app family, and selects “מצא את המצלמות שלי”. The authorized server assesses the selected existing site. It does not claim that a web browser scans the LAN.

## I DON'T KNOW MY SYSTEM

The first selection is “אני לא יודע איזו מערכת יש לי”. Guidance uses app/device brand/model. An already-authorized local Connector can supply discoveries. Without that capability, the Product explains the next identification step rather than guessing or declaring hardware mandatory.

## VENDOR ACCOUNT LINKING

No live vendor OAuth integration is added in this PUSH. A documented API without an implemented adapter yields integration pending. There is no fake authorization button and no request for a vendor cloud password.

## MOBILE LOCAL DISCOVERY

Strict scoped, short-lived metadata/permission contracts exist in `mobile-camera-setup.ts`. Native discovery and real OS permission QA remain coverage gaps. Current Product truthfully says local phone discovery is unavailable. The phone is a temporary setup agent, never a promised permanent bridge.

## DIRECT CONNECTION

Server-owned adapter proof must demonstrate secure persistent access without on-site customer service. Current production plan supplies no verified direct proof. QA fixtures prove ranking only; they do not represent a live direct integration.

## SOFTWARE CONNECTOR EXCEPTION

Reuse an authorized healthy site Connector. Otherwise ask whether a computer normally remains on-site and connected. Do not ask the customer to choose protocols or copy IDs. Current automatic installer is unavailable and is shown as unavailable—not as a completed installation.

When discoveries arrive, customer explicitly selects a camera. Saved credentials are not requested again merely because a test is pending. Updating credentials is a deliberate action. Selection changes clear typed credentials. Camera names can be confirmed/edited. Existing device APIs perform encryption, testing and activation; no manual DB path is added.

The panel polls read-only state every 10 seconds when visible, without polling during its own mutation. Stale Connector heartbeat is not healthy. Activation requires current source/device evidence server-side. Installer → automatic bind → automatic discovery for a new customer is still NOT PROVEN; this is the PUSH 17 blocker.

## PHYSICAL GATEWAY EXCEPTION

Only offer a local appliance for a verified local path when no suitable always-on computer is available. Explain the scoped reason. Do not state that all possible vendor paths are technically impossible. Unknown recorder remains identification-required; a missing cloud integration is not hardware necessity.

## MULTI-CAMERA DVR/NVR

One system enters the same high-level wizard. Existing canonical DVR discovery/mapping is preserved. Multi-channel customer self-service is not newly verified; Advanced setup still carries technical work. Do not advertise a technician-free recorder integration until that journey passes.

## SINGLE IP CAMERA

Tapo is the real reference. Credentials belong to the local camera account and are entered only in the secure Product form. Generic local protocol candidates reuse the same high-level flow; exact vendor/profile integration still needs capability validation.

## MIXED SITE

The existing Home retains 10 DVR sources and one Tapo. Different transports do not create separate homes or customer camera lists. This change does not re-enroll, rebind or recreate existing cameras.

## FAILURE / RECOVERY

Bounded categories cover wrong credentials, offline device, network reachability, permission denied, vendor authorization, unsupported firmware, integration missing and local-bridge need. Retrying a transient error is bounded; no automatic insecure downgrade. Category/retry policy is implemented; not every adapter yet emits every normalized category.

## SUPPORT ESCALATION

Assessment returns a random diagnostic ID with best-effort audit linkage. Support receives that reference, not passwords or LAN topology. Manual support remains an undesirable funnel outcome; its complete automatic measurement is still pending.

## CUSTOMER-FACING LANGUAGE

Use “רכיב חיבור”, “נמצאה מצלמה”, “בודקים את החיבור”, “מוכנה להפעלה”. Do not equate DISCOVERED with CONNECTED, or saved credentials with monitoring. Advanced protocol details remain optional. New UI is local/unreleased; browser visual verification was unavailable in this session.
