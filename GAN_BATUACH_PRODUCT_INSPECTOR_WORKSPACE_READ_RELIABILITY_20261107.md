## Defect and correction

`/dashboard/inspector` previously used `gardensRes.data ?? []` without checking `gardensRes.error`. A failed assignment read therefore displayed the verified approved-unassigned state, including a false zero task count. The same fallback turned failed required-inspection, inspection-history, violation, complaint and task reads into false empty lists, safe-looking zero metrics and an incorrect "no upcoming inspection" hero.

The page now refuses to infer Garden assignment from an unsuccessful or missing assignment payload. It renders an accessible unavailable state with no Garden operations until assignment can be verified. Valid zero assigned Gardens retain the existing approved-unassigned composition and preliminary-Garden entry. With verified Garden assignment, each secondary read is evaluated independently: successful lists remain visible, failed sections state what is unavailable, unavailable metrics display an em dash with an explicit label, and start-inspection context is withheld when the required-inspection read fails. Query bounds, Inspector ID/Garden ID filters, canonical `requireApprovedInspector` authority and role permissions are unchanged. No private query error detail is exposed.
