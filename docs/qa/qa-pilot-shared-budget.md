# Isolated QA media budget

The loopback server factory is opt-in and has no standalone launcher or upstream addresses. It denies construction in a Production environment. Do not route existing live viewers to it. A future launcher must use private QA-only adapters and a transport that cannot route to Production services or bypass the coordinator.

The operator must verify one signed, short-lived approval bound to the worker nonce, run ID, account, site and all eleven allowed source IDs, with the CH1 source designated. Every media request must authenticate the same viewer and tenant. Adapter functions are trusted: they must verify upstream source ownership and grant expiry, accept abort, bound reads to maxBytes and return a single safe media object. The signer and account/site verifier are supplied by the isolated QA environment, never by a client-controlled header. The trusted launcher calls issueManifest only after authenticating the viewer. It returns one 30-second bearer URL; the server signs each playlist or segment path, rewrites the playlist to same-origin budgeted URLs, and revalidates the original session and tenant on every request. Replacement invalidates the previous URL and repeated requests within the active lease consume the same shared budget. The URL is a bearer secret, so strip queries from reverse-proxy, app and tracing logs and never send it to another origin. Native and browser clients can request the URL without custom headers; actual device behavior and refresh orchestration still need qualification.

A private directory on the approved external volume must be verified by an assertMounted adapter for every reservation. Each run creates one exclusive 32-byte ledger file, fsyncs cumulative reservations before sending, and consumes the same allowance for both routes. No payload is written to disk. Canceled delivery is charged. One transfer at a time bounds concurrency. The run is capped at 30 minutes and 100 MiB of response bodies; CH1 expires after five minutes from its first authenticated media request and rejects future CH1 media. A new worker cannot replay the prior worker's approval, even if the ledger disappears. An unavailable or altered ledger closes the live run.

The generic clients and existing CH1 gate are unchanged. Before activation, an isolated launcher must bind readGeneral/readCh1 to the approved sources with no alternate media path, preserve the separate CH1 grant checks, verify the volume, and record the exact build/package IDs. No actual media is read by the checked-in tests.

The code requires no paid service. The 100 MiB cap counts media bodies, not TLS or upstream traffic. Obtain the current provider egress and budget snapshot before approving any real run, and allow a conservative margin below the cost ceiling. After the run, close the server and revoke the short-lived approval; retain only the private fixed-size budget receipt and remove it per QA retention.

The isolated server requires the exact 40-character candidate SHA and a trusted registry for one site: ten DVR sources (one CH1) and one software connector source. The signed run must cover exactly that registry. Each adapter receives its pinned binding and must enforce the gateway, stream and profile on every read. The launcher must supply the expected SHA when issuing a manifest; each successful media response includes the verified build header. Keep Vercel and direct edge grant issuance outside this isolated run; a real QA deployment needs a trusted same-origin issuer and a transport that strips query strings from all logs before the native package is pointed at it.

For a QA-only Web deployment, set OBSERVER_QA_BUDGET_ENABLED=1 and configure OBSERVER_QA_ISSUER_PORT, OBSERVER_QA_ISSUER_KEY, OBSERVER_QA_RUN_ID and OBSERVER_QA_BUILD_SHA in the isolated host. The shared Observer playback route verifies the logged-in site and camera binding, then calls the authenticated loopback issuer. The issuer independently pins site, gateway, stream, profile, expected SHA and live viewer session. This mode rejects legacy channel playback and direct cloud Edge grant redemption. Only /qa/ media routes should be exposed by the private QA reverse proxy; keep /internal/issue local. Neither handler logs submitted tokens or signed URLs. The separate infrastructure proxy must redact query strings from access logs and must not expose any direct QA upstream. Existing production hosts must not be reachable from QA readers. This repository provides reader injection and verified registry bindings; an approved runtime launcher still needs to supply real readers and a session verifier. No native change is required for URL attachment; verify the signed com.digitalobserver.app.qa build and its origin before real use.
