# GB-M10 atomic activation closure

Task: `GB-M10-OWNER-ONBOARDING-ATOMIC-ACTIVATION-CLOSURE` under cumulative GB-M40 validation. Source Development SHA: `737e6e61dc4e61cc2211703d4e44f379b4ced7fb`.

The existing activation RPC already locks one Garden and commits membership, role, consent, trial subscription and lifecycle in one transaction. The HTTP final-submit path nevertheless saved Garden, onboarding, Classroom and fee draft rows through separate service-role requests before calling that RPC. A stale request could therefore continue after successful activation. In a fresh, disposable database restored from the protected isolated-QA backup (SHA-256 `e939d080a7c272e83af681356055015760d5c47bc0e100ec7aa289cf35afccae`), a synthetic Manager activated a draft and a stale draft write changed Garden/onboarding/membership from `active/active/active` to `pending/onboarding_in_progress/active`. The entire probe rolled back; canonical QA retained 15 Gardens and the disposable database was removed.

Final submission now calls only the activation RPC over the previously persisted review-step draft. The existing UI saves the draft when moving into review. This leaves no final-submit draft, Classroom or fee writes outside the activation transaction and permits an idempotent retry to reach the RPC even when the Garden is already active. Ordinary save/resume remains available while pending.

A forward migration rejects an active Garden's return to pending/onboarding-in-progress and an active onboarding record's return to draft states. These row-level guards protect against stale save requests that began before activation; they do not block ordinary active-Garden profile edits or legitimate suspension/archive lifecycle paths. The SQL regression creates only synthetic state inside a rollback transaction and checks incomplete activation denial, no partial consent/authority, successful activation, same-key retry without duplicate membership/subscription/consent/event, manual provider truth, foreign Manager denial, both stale-write guards and allowed active profile editing.

No payment provider is activated, no charge or invoice is created, no real Garden/customer is touched, and no new paid dependency, table or sensitive data category is introduced. The new triggers add constant-time checks to Garden/onboarding updates; measured provider cost impact remains unverified, with expected new fixed monthly commitment ₪0. The existing 14-day manual trial and document-summary contract remain unchanged; actual private-document verification is a separate product requirement. Production and main are untouched. This scoped QA does not replace full Product, security, owner-visual, supplier-cost or recovery release gates.
