# Observer QA pending native Push registration across account switch

2026-11-17. Isolated local worktree based on `integration/development` `72edd07346e939fefe979fc0a4f6198e83ecf1b8`. The native runtime previously stored `pendingPushRequest` with request ID and Site only. On A→B bootstrap it cleared persistent Site/queue but not the in-memory request; a delayed provider registration callback could continue for the same Site under B. The incoming notification preview already ignores payload title/body, and action links still pass the authorized server route. The identified gap is registration intent ownership, not a proven camera/resource disclosure.

The fix binds a pending request and provider registration attempt to the authenticated profile, clears both on known account switch and 401, ignores callbacks without a matching current owner, and rechecks owner after reading native preferences. The native registration request now includes `expected_profile_id`; `/api/push/register` compares it to the server-authenticated profile before any token write. This closes the late-callback cookie-switch window for the honest client. The field is optional for existing callers and **is not app attestation or a trusted product identifier**. Existing cross-app token isolation remains separately blocked.

The route harness proves A's expected profile is denied under B's authenticated session while B's own request remains allowed; pure owner contract and runtime source assertions cover A→B, missing owner, 401, generic previews and authorization route.
