## Source decision and approval boundary

The mock test **disproves** that stopping six services plus blocking API/direct-DB ingress is a complete source writer barrier. A Docker administrator can still create a container with the DB or Storage volume mounted, even with no network. Also, a guest-local watchdog cannot unpause containers while the guest daemon remains unavailable, and a VM-wide failure was not tested. Therefore the real quiescent capture and source rehearsal are **not ready for owner approval**. Do not convert the fail-closed dry-run to PASS or begin backup/restore.

**One exact technical next step:** establish and independently test an exclusive Docker/VM maintenance lock or another enforceable prevention of new protected-volume mounts for the entire source window, plus a bounded daemon-unavailable recovery path that can restore paused exact IDs without assuming automatic Docker recovery. If either cannot be provided without interrupting the database, reject quiescent capture and re-evaluate the separately scoped online PostgreSQL backup plus Storage consistency barrier. Only after these facts are proven should a narrowly worded Development-only source rehearsal be presented to the owner. No broad approval request is justified by this unit.
