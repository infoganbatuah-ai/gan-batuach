## Exact preboot isolation blocker

The existing runner at `run-isolated-encrypted-restore-architecture-qa.mjs` creates a Lima `vmType: vz` guest with `networks: []`, `mounts: []`, `portForwards: []`, and no proxy propagation. It then **starts the guest**, observes a default route, starts Docker, and only afterward installs an output-deny firewall. This can bound egress after setup, not from the first instruction of boot. Lima's [default user-mode network documentation](https://lima-vm.io/docs/config/network/user/) states that it is enabled by default and allows outbound connections; the [v2.2-era network configuration](https://github.com/lima-vm/lima/blob/master/templates/default.yaml) says `networks: []` only disables extra named networks. The installed `limactl` is 2.2.0; the documented `networkOpts.hostLoopback: false` option is from 2.3 and still permits outbound connections and access through other host addresses. A guest firewall installed after startup cannot prove no preboot egress. No host-side, preboot-disconnected virtual NIC/transport was qualified here. **Do not start this guest with the owner-accepted unsigned image.**
