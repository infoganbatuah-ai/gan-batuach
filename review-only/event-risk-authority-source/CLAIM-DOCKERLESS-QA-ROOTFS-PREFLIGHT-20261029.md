## Review-only contract and safety decision

`dockerless-rootfs-preflight.mjs` parses the already verified Docker-save without writing or extracting anything. The metadata contract requires 29 ordered layers; rejects absolute/traversing member paths, duplicate members, special nodes, escaping symlink targets, writes through symlink parents, and unsafe hardlinks; and models lower-layer whiteout and opaque-directory removal. It has a 100,000-member metadata bound. Every successful result explicitly says `OFFLINE_METADATA_ONLY` and `extractionAuthorized: false`.

A naive `tar -xf` or host-side chroot is **not qualified**: the real image's thousands of links require a guest-local extractor with no-follow directory operations, container-root interpretation of absolute links, Docker/OCI whiteout semantics, ownership/mode handling, resource bounds and rollback. `chroot` alone does not create a network or privilege boundary. The Ubuntu guest might provide the needed base tools, but no guest execution, dynamic-linker compatibility, PostgreSQL startup or restore has been proven. No third-party input or download is proposed. The only candidate using the two approved inputs is to materialize this same verified rootfs inside the disposable encrypted Ubuntu guest **after** measured egress denial, run PostgreSQL over a Unix socket as an unprivileged guest-local account, and replace every Docker-specific synthetic restore/cleanup operation with an equivalent guarded guest-local operation. That candidate remains blocked until the extractor and all existing isolation/cleanup gates are implemented and independently qualified; this file does not enable it.

The approved QA attestor public key and fingerprint remain `null`, and the runner calls `assertQaAttestorPinned()` before reading either input or making scratch storage. No key was generated or pinned. Backup status remains `COMPONENT_BACKUPS_ONLY`; independent restore remains `NOT_RUN`.
