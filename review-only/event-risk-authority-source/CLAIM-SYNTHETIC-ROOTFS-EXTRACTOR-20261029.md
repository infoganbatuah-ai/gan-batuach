# Synthetic rootfs extraction probe — 2026-10-29

This is a review-only local probe of small synthetic TAR layers. It does **not** extract the approved Supabase Docker-save, start an Ubuntu guest, run chroot/PostgreSQL/SQL, or qualify an independent restore. The real-QA entrypoint remains hard-disabled (`APPROVED_REAL_QA_EXTRACTOR = None`), and the existing runner has no import of this module. The separate attestor pin remains `null`.

`synthetic-rootfs-extractor.py` uses only Python standard-library APIs already present in the approved Ubuntu ARM64 manifest. It accepts in-memory synthetic layers only (8 MiB per layer, 32 MiB total, at most 4,096 members), verifies each supplied SHA-256 and layer order, and prevalidates all metadata before writing. The only output target is a new empty private `do-qa-synthetic-rootfs-*` directory directly under an owner-private temporary parent. Every descendant lookup is relative to an open root/parent directory descriptor using `O_DIRECTORY|O_NOFOLLOW`; files use `O_EXCL|O_NOFOLLOW`. There are no absolute host symlinks, broad path deletion or shell commands. On failure it checks the exact scratch inode/device before anchored cleanup. A successful synthetic receipt can be cleaned only against that same inode/device.

Synthetic tests exercise traversal, relative/absolute symlink escape, symlink-parent writes, hardlinks, OCI-style whiteout and opaque lower-layer handling, duplicate and out-of-order members, FIFO/device denial, UID/GID/mode and size caps, stripping setuid/setgid/sticky/world-write file modes, wrong/private target checks, mid-layer failure cleanup, wrong-inode rollback and an unchanged sentinel outside the target. These prove only the local synthetic fixture behavior. The same code has **not** been run in the Ubuntu guest and is not authorized for the real archive.

Focused local result: 13/13 Python synthetic tests PASS. The pre-existing offline image/rootfs contract tests remain separate; no real archive extraction was attempted.

Remaining before any real QA rootfs materialization: independently approved attestor pin; guest-measured egress lock/no host mounts; reviewed guest-local scratch and ownership proof; a bounded rehearsal of the actual link-heavy 29-layer metadata (including package-specific uid/gid, modes, directory semantics and dynamic libraries); fault/cleanup rehearsal in the disposable guest; and replacement of all Docker-specific runner operations. Source UID/GID and directory modes are intentionally **not** preserved by this synthetic probe, so it is not a drop-in container runtime or a validated PostgreSQL environment. Backup status stays `COMPONENT_BACKUPS_ONLY`; independent restore stays `NOT_RUN`.
