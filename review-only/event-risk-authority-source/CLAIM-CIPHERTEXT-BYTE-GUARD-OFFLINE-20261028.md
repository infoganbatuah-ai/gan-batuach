# Post-age ciphertext byte guard — offline qualification

**Scope:** Development review-only helper, no source operation. The previous synthetic rehearsal `ce66ce0a` was successful for dummy data but its 100 ms file-size polling was not a hard cap. This unit replaced that polling with `bounded-ciphertext-writer.mjs` and connected it to `run-isolated-cold-backup-rehearsal-qa.mjs`. The full VM rehearsal was **not rerun**.

The helper accepts only the post-`age` binary output stream. It opens one previously nonexistent file in a private owner-owned directory with `wx`/mode `0600`, counts bytes before forwarding each whole chunk, rejects a crossing chunk before any of its bytes are written, waits for both stream completion and upstream process success, and removes its newly created partial file on cap, floor, upstream, stream or abort failure. An existing file is neither overwritten nor removed. A failed upstream-abort callback is surfaced as a distinct error. The caller must terminate source and age processes on abort; the synthetic runner does so. There is no plaintext archive file in this path.

Constants: **1,073,741,824 ciphertext bytes maximum** and **3,221,225,472 free bytes minimum**. The helper measures free space on the ciphertext destination filesystem, requires headroom for the **entire** maximum ciphertext file before opening it, and conservatively charges all accepted-but-possibly-buffered bytes before each write. This bounds the helper's own accepted output. It is **not a hard system-wide free-space guarantee**: unrelated processes can consume disk after a check, and filesystem accounting/writeback can change independently. A later source adapter must retain an operational disk monitor and an abort/restart deadline.

Focused offline tests: **16/16 PASS** with actual temporary files, a real nonzero child-process exit, and stream failure/abort probes. Covered: exactly at cap; one byte over; oversized single chunk; crossing between chunks with no partial crossing write; prospective free-space failure; insufficient initial full-cap reserve; buffered-byte reserve; age-like nonzero exit; source failure after apparently complete ciphertext; stream error; midstream abort; abort with hung upstream exit notification; pre-abort; failed upstream termination callback; `wx` preservation of an existing file; removal of newly partial output. Tests used a small limit to exercise boundaries without allocating 1 GiB. All test directories were removed.

**Limits and next gate:** These are deterministic offline tests of the byte guard, not a rerun of the seven-service VM rehearsal and not proof of a current original `gbi` backup. The original-source adapter, exclusive-writer gate, fresh independent owner-key check, graceful exact-ID stop/restart controller and explicit owner downtime/current-rollback risk decision remain required before touching `gbi`. No source SQL, stop/start, capture/restore, private key, cloud, Production or Home action occurred.
