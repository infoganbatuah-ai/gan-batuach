# Synthetic rootfs extractor adversarial review — local only

Scope: `synthetic-rootfs-extractor.py` and its small in-memory TAR fixtures. No real Supabase archive was opened, no guest/DB/Docker/SQL was run, and `APPROVED_REAL_QA_EXTRACTOR` remains `None`.

## Concrete findings and fixes

1. `_target_fds`/cleanup formerly checked `realpath(parent)` and later opened the parent by pathname. A same-user concurrent replacement of an **intermediate** directory with a symlink could redirect extraction to a different private target. The new `_open_scratch_parent` traverses every component from the temporary root using directory FDs and `O_NOFOLLOW`; the adversarial test swaps the component exactly before open and verifies the other target and external sentinel remain untouched. The test failed before the fix.
2. `_remove_at` formerly used `stat` then opened a child directory without comparing its inode. A swap at that point could delete an unrelated replacement directory during rollback. It now compares `fstat` with the prior `stat`, and rechecks the path before `rmdir`. The adversarial test moves a sentinel-bearing directory into the target at that exact boundary. The test failed before the fix and now denies deletion.
3. A PAX GNU sparse extension can be presented as a regular TAR member. It was accepted despite the intended small regular-file-only contract. The extractor now rejects any `TarInfo.sparse` value; a crafted PAX sparse test failed before the fix and now passes. PAX path override traversal and GNU sparse member type are also tested for denial before writes.

Previously present tests cover nested symlink-parent refusal, hardlink-to-symlink denial, whiteout/opaque same-layer ordering, special nodes, duplicate/path traversal, owner/mode stripping, digest and size/member caps, fault rollback and disabled real entrypoint. Layer bytes are capped at 8 MiB each/32 MiB total, members at 4096, file bytes at 4 MiB; TAR is opened in uncompressed `r:` mode and parsed before writes. These bounds reduce memory and CPU exposure but are **not** a measured worst-case resource guarantee on Ubuntu.

Local test result: 16/16 Python tests on macOS Python 3.14.8; Python 3.12 grammar parse passed. [Python 3.12 `tarfile` documentation](https://docs.python.org/3.12/library/tarfile.html) documents the PAX/GNU sparse fields used by the check. Actual Python 3.12 Linux behavior, filesystem semantics, concurrent same-UID adversary behavior after the final path recheck, and extraction of the real 1.33-GB image remain **unproven**. In particular, no Python pathname-based `unlink`/`rmdir` sequence can be presented as an atomic inode-bound delete under a malicious same-UID rename race. Future guest qualification must use a dedicated private parent/UID, remeasure identity and cleanup, and fail closed if unexpected concurrent mutation is possible.

The tests create only disposable synthetic directories under the system temporary folder. Their teardown removes them; a post-test scan found no `do-qa-synthetic-parent-*` or `do-qa-parent-*` directory. `/private/tmp` had 9,296,280 KiB available at the final measurement, above the required 3-GiB floor. This local review does not change backup status, recipient ownership, Model A Tenant/Site rules, or any real restore gate.
