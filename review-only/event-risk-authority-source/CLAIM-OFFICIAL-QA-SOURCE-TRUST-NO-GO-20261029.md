# Two-source QA trust review — NO-GO for replacing the independent attestor

This is a review of recorded source facts and existing code, not a new download or file verification. The exact artifact digests/sizes below were supplied by the coordinator's prior receipt; this unit did **not** rehash the two large files or verify a GPG signature. `official-qa-source-trust-review.mjs` is disconnected from the runner and always rejects execution, including when every recorded fact matches.

## Code decision

`synthetic-qa-image-input.mjs` deliberately has `APPROVED_QA_ATTESTOR_PUBLIC_KEY_PEM = null` and `APPROVED_QA_ATTESTOR_SPKI_SHA256 = null`; the runner calls `assertQaAttestorPinned()` before reading artifacts or creating scratch. `synthetic-rootfs-extractor.py` independently has `APPROVED_REAL_QA_EXTRACTOR = None`. Neither gate is changed. The new review-only classifier rejects mismatched receipts and **still returns NO-GO for exact matches**. It ignores asserted `publisherSigned`, `httpsFetched`, and `ownerSelfSigned` flags. This prevents a self-asserted receipt or registry digest from being mislabeled as independent signature proof.

To propose a different executable policy, an authorized reviewer would need to establish a trusted source/publisher binding for the exact Supabase image (a verifiable publisher signature or explicitly reviewed alternative trust model), prove the registry-manifest-to-local-tar content relation using actual bytes/metadata, and review the combined QA scope, expiry, file custody and real extractor. Any such policy change requires separate code and tests; no self-generated attestor may fill this gap. Even then, image trust alone would not prove a safe guest, PostgreSQL restore or Development recovery.

**Result:** official-source facts support an Ubuntu signed-artifact check and a Supabase integrity check, but do not meet the existing independent attestation gate for both artifacts. Guest execution remains disabled. Backup status remains `COMPONENT_BACKUPS_ONLY`; independent restore `NOT_RUN`. No owner key, real archive extraction, guest, Docker, SQL, provider mutation, Production or remote Git action occurred.
