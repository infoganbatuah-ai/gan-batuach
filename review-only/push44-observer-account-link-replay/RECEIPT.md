# Observer QA pending resource after account switch

2026-11-17. Isolated local worktree based on `integration/development` `72edd07346e939fefe979fc0a4f6198e83ecf1b8`. In `components/digital-observer/observer-mobile-runtime.tsx`, the authenticated bootstrap already cleared native Push site/queue state when the known profile changed, but left `digital_observer_pending_link_v1` and its cold-start marker in `sessionStorage`. A resource link saved under account A could therefore be replayed under account B. The server rechecked B's Site/resource authorization, so this was not an authorization bypass; if B independently had access to that resource, however, the A-originated navigation intent could still open under B.

The scoped fix clears the pending resource and launch marker **only when a previously known owner differs from the newly authenticated profile**, before taking any pending link. A link received before the first known login remains available for the intended one-use cold-start flow. The existing server authorization remains mandatory; no link is promoted to a session or bearer token.

Focused local tests exercise A→B switch, preservation of an unbound first-login link, cleared one-use replay, cold-start marker reset, logout/401 and cross-Site denial. `node --test scripts/qa/check-push44-native-account-state.mjs scripts/qa/check-push44-android-deeplink-replay.mjs` 10/10 PASS; focused lint and TypeScript validation PASS. The route test is an isolated harness, not a physical iPhone account-switch or live Supabase proof. No device, live service, SQL, Push, remote Git, Home or Production action occurred.
