# Development playback authorization for Gan Batuach

The local Digital Observer provider matches Gan's `cameraPilotGrant` interface at `6830f794`. The scope is Development, live WebRTC and the designated synthetic garden. This module has no route, signing key, media connection or environment switch. The application must supply the trusted server integrations below before accepting a grant.

| Control | Local contract |
| --- | --- |
| Gan assertion | Sign the ASCII base64url-encoded JSON payload with the dedicated Ed25519 Development key. Send `payload.signature` with an unpadded base64url signature. Required fields: `version: 1`, `issuer: "gan_batuach"`, `audience: "digital_observer:gan_camera_pilot"`, `environment: "development"`, `operation`, `binding`, `sessionId`, unique random `jti`, `issuedAtMs`, `expiresAtMs`. For `redeem` include the exact handle. The maximum assertion lifetime is 45 seconds. Keep the private signing key on the Gan server. |
| Exact binding | Gan supplies `viewerId`, `role`, `gardenId`, `siteId`, `cameraId`, and `protocol: "WebRTC"`. The provider accepts only the server-configured `qaGardenId`. DO resolves the active session, permitted role and authoritative garden-to-Site/tenant and camera-to-source/Gateway/stream mappings in the designated QA environment. A missing or revoked link fails closed. |
| Issue and redeem | Gan uses `issue(binding)` and `consume(binding, handle)`. DO returns the same binding with `version: 1`, `environment: "development"`, `capability: "live_playback"`, `recording: false`, the operation, opaque handle and expiry. Gan publishes only the opaque handle and expiry. The server store must reserve each issue assertion's `jti` until expiry and compare the complete stored scope, current expiry and revocation state in the transaction that consumes the handle. |
| Revocation | An authorized backend operation revokes the handle in the same atomic store. The resolver rechecks viewer and session access at redemption. The future delivery boundary must stop subsequent media independently of whether the one-use handle was already consumed. |

## Required before external playback

The local implementation now includes `openGanCameraPilotSyntheticEdge`. It uses one private SQLite file per synthetic window on one host. Two independent connections share the same durable redemption and byte counters. The caller configures the exact scope and absolute deadline. The adapter commits byte reservations before a synchronous synthetic sink, retains reservations after failed writes and signs a stopped-window receipt with a separate Ed25519 key. The receipt always carries `playbackQualified: false`. The recorded sequence counts synthetic submissions and does not measure rendered client frames.

1. Gan owns server-side role resolution, current user/garden authorization and assertion signing. DO owns the dedicated verification key, authoritative QA mappings, transactional store and the private media endpoint. The SQLite adapter requires exclusive operator custody and one shared file on a single host. A replicated deployment needs a shared transactional store or a verified single authoritative delivery process. Keep the Home path and PR #677 separate. Neither the integration health response nor a successful grant is playback evidence.
2. Reserve and meter at the actual DO serving boundary. Set one absolute 300-second deadline, one source, one stream, one viewer and 104,857,600 cumulative media bytes. Reconnect uses the same deadline and byte counter. Verify separate request and provider traffic limits, including signaling, retries, and protocol overhead. Stop delivery on missing accounting or revocation. These limits are declared locally; enforcement and cost remain open.
3. Produce a signed DO receipt from the serving boundary only after observing frames in the authorized client. Bind the receipt to the environment, exact build SHA, window and verified tenant/garden/Site/camera/source, pseudonymous session/viewer, and edge identity. Record start and termination, advancing frame observations, request/byte totals, replay and denial outcomes, reason for stop, and cleanup. Specify receipt expiry and verify it against the designated DO public key. Keep credentials and stream URLs out of receipts. Missing, invalid or stale evidence keeps playback qualification false.
4. Qualify the actual transport's races, live-session revocation, buffered output cancellation, limits and signed receipts in the synthetic garden. Qualify the CH1 window separately after stabilization and owner approval.

## Protected loopback transport follow-up

The loopback Development host accepts `POST /pilot/whep` with `Content-Type: application/sdp`: a single video receive-only offer, at most 16 KiB, without supplied ICE candidates. Gan first verifies its current QA user session and current role and then sends two server-only headers. `Authorization: Bearer <service-token>` authenticates the Gan server using a DO-configured SHA-256 digest, and `X-Gan-Pilot-Assertion` carries the fresh Ed25519 `redeem` assertion with its opaque handle. The DO host verifies the configured Gan public key and resolves the verified viewer, role, session and camera identifiers against the authoritative QA mapping before consuming the grant. This mapping comes from the injected server resolver, never from the SDP or browser fields. The lab uses a fixed synthetic mapping; the product resolver and private Gan-to-DO transport remain to be connected.

Success returns `201 application/sdp` and `Cache-Control: private, no-store`, with one local passive TCP ICE candidate and no upstream URL or service credential. Use the exact loopback Host and omit Origin for Gan's server-to-server request. The listener rejects foreign origins. The upstream WHEP request uses a dedicated server-only read credential for `do-pilot-reader`. Configure the media service to reject requests without that credential and keep the publisher identity separate. Deny failed authorization with 403, invalid offer with 400, repeat use with 409, wrong media type with 415, and downstream failure with 503. No reconnect or renegotiation is admitted in this fixture.

When Gan observes logout, access revocation or an authorized stop, its trusted server sends `POST /pilot/revoke` with the same service bearer and `Content-Type: application/json`. The body is exactly `{"handle":"<active-opaque-handle>"}` and at most 256 bytes. A match closes both sockets before recording durable revocation and returns 204. Unknown handle or service returns 403, malformed JSON returns 400, and failed persistence returns 503 with the local transport already stopped. An idle connection also closes at the deadline, and the byte ceiling charges encrypted server-to-viewer chunks before forwarding. Transport bytes do not include operating-system and provider overhead.

The lab must pin the upstream to the isolated loopback peer. A deployed design must isolate the upstream listener from the viewer network, authenticate signaling, bind the requesting session to the ICE/DTLS exchange, propagate session and grant revocation, and verify actual serving and provider limits. The synthetic receipt remains `playbackQualified: false`. Count observed frames through the receiver, record them separately from byte reservations, and distinguish already-buffered output from further transport. No physical or external playback is authorized by the fixture.
