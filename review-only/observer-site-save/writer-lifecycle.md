## Forward and inverse acceptance

1. **Identify the baseline independently.** Reconcile PG17 version, QA project, operator identity, registry, effective table/schema/function/default ACLs, role paths across the cluster, API-exposed schemas and target isolation. The prior hosted receipt covers 106 explicit columns, seven migration-matched functions and three triggers. The new original-digest-review projection uses a different fingerprint over the touched existing catalog. Capture that fingerprint with the same operator and search path at the independently retained pre-change recovery point. Digests and custom session settings are comparison inputs, not authorization. Cross-database dependents, role-level privileges, unrelated concurrent DDL and credential inventory require independent inspection. Keep other DDL and admission closed through each lifecycle transaction.
2. **Install only on a separately approved restored rehearsal copy first.** Follow INSTALL in the inventory. It rejects collisions rather than adopting pre-existing objects. It installs the atomic core, generic writer, base RLS, pinned pair and final ACL boundary together. Generic EXECUTE exists only in the uncommitted transition and the pair package withdraws it before commit. No pin, sign-in, new API client, role password, JWT or Site is staged by installation. Capture and review two post-install digests before opening admission: original-digest-review for the existing surface *as installed*, and new-digest-review for new roles, memberships, namespace, types, relations, constraints, indexes, policies, trigger metadata and function bodies. The trusted operator must review the actual installed delta against the manifest before accepting either receipt.
3. **Withdraw with admission already closed.** Independently stop issuance, revoke any issued QA credential at its source, stop pin staging, close the restricted route, and prove no active or pooled writer session can continue. An expiring token or a membership REVOKE does not drain already running calls. Record the evidence digest. The SQL gate takes the pin lock NOWAIT, checks expiry, verifies both installed receipts and checks the effective boundary before any reversal. Remove the authenticator edge ahead of pair rollback. The temporary return of generic EXECUTE in the prior pair inverse remains uncommitted and is withdrawn before commit. A failure rolls back the entire catalog transaction; keep the external admission closed during investigation.
4. **Preserve history and compare.** Hold both receipt tables locked while verifying custody, visibility and dependencies. The default path leaves operator-owned history with its FK chain intact. A separately selected drop_empty_history mode may remove both tables and then the schema using RESTRICT only if both are demonstrably empty. If either contains rows, retain both. Drop only the two candidate roles last. Require exact equality with the original catalog receipt before commit. Raw ACL differences including NULL versus explicitly default ACLs or ordering cause a stop even if effective privileges appear equivalent. Never write catalogs directly to force a match. Never delete a Site to undo an installation. An approved rehearsal must compare row identities/digests and later writes independently of the metadata check.
