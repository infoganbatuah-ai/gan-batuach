# Atomic Site save candidate

**Local review only. Hold the route change and SQL together.** The route uses the current Observer session and submits one RPC after validating the form and checking management access for edits. Missing package fails before address resolution. Missing RPC, missing permissions and unconfirmed results fail closed. There is no fallback to a sequence of writes. An ambiguous transport response requires reconciliation before another create attempt.

## Transaction

The existing start_digital_observer_trial requires an existing Site. It cannot roll back Site creation by a preceding HTTP request. The current commercial service likewise issues independent requests for subscription, grants and financial audit. The candidate puts all seven affected tables in one PostgreSQL command. It takes the Observer account lock before counting Sites and selecting a draft, locks the existing Site/subscription for edits, checks the package and trial before writing, and propagates write failures to PostgreSQL. The accepted clock, package snapshot and entitlement keys are shared by the entire trial. The ten grant IDs and audit correlation use the commercial service's HMAC namespaces and delimiter.

The first release candidate accepts owner edits on standalone Sites of the same type. It retains an existing eligible subscription and expiry on same-package edits, and rejects attempts to replace a used trial. It updates the draft linked to the edited Site. Delegated operators, administrators and organization members who do not directly own the standalone Site are denied this billing-affecting operation by the route and the database. Existing general Site-management permissions are unchanged. The database precheck deliberately rejects an inactive account or missing trial/grace deadline.

## Qualification and release gates

Run `node --experimental-transform-types --test review-only/observer-site-save/*.test.mjs` with the locked dependencies. The route test uses isolated session/transport fixtures. The SQL tests execute the exact function body in an ephemeral in-process PGlite database using DDL excerpts from the referenced repository migrations. The test schema supplies a synthetic session and executes the positive path as its fixture owner. Tests compare full table contents across errors, including failure of the last financial audit insert. They do not establish a deployed Supabase permission model, simultaneous independent PostgREST sessions, or a real saved Site.

The SQL opens with an unconditional abort. Its proposed function is SECURITY INVOKER with an empty search path. Its installation transaction removes EXECUTE for PUBLIC, anon, authenticated and service_role. No role grants or RLS changes are proposed. This is the deliberate release blocker: prove a narrow callable boundary that preserves real session authorization and server-validated address/privacy fields while permitting the required billing/audit writes. Ordinary authenticated sessions cannot be given general billing-write access. Review role inheritance, deployed triggers and all relevant RLS policies, including Site visibility during quota counting. Run the real owner/non-owner/anon matrix and concurrent create/update tests against an authorized isolated target. The follow-up writer candidate below adds transaction receipts for a lost response.

## Rollback

Before installation, discard only the candidate change. Before enabling traffic, keep Site-save closed at ingress; in an approved schema transaction remove only the new function by exact signature with RESTRICT once its call sites are disabled. A failed save rolls back its own transaction. For a successful save or a response lost after commit, preserve Site, membership, draft, schedule, subscription, grants and audit. Reconcile those rows by actor and Site before any retry. Never delete records to compensate for a transport error. During rollback keep the write endpoint closed until a compatible atomic writer is available. Do not re-enable the previous partial-write path. No rollback was exercised against hosted data.

## Scoped writer and replay candidate

The form retains one submission UUID in per-tab storage scoped to the profile and account type until the server acknowledges the save. Both JSON and form submissions require a UUID. The server hashes the normalized form before adding clock- or provider-derived fields. A reused key with different form data returns conflict. Each owner owns a separate key namespace. An ambiguous save must retain its key across retries; if the client loses the key, inspect existing Sites before starting a different submission.

The route verifies the user, active Observer session and signed user claims. It forwards the verified actor, session ID and expiry with its server-generated patch through the local-only adapter. The adapter requires a dedicated short-lived caller token and refuses a service-role token or a non-loopback destination. The reviewed wrapper accepts only the dedicated PostgREST role, rechecks the live Auth session inside the database and requires a directly owned standalone Site for updates and receipt reads. Its private executor role has no login, superuser privilege or RLS bypass. Its account lock serializes receipt lookup, the underlying save and receipt insertion in the same transaction. Only that executor may call the underlying function. Keep receipt rows and original results across rollback; they contain customer data and require the same retention and access controls as the underlying Site.

**Release blocker.** No independently qualified dedicated PostgREST caller credential, executor policies or deployed ACL evidence exists in this checkout. The fixture installs only synthetic roles in memory. Do not give authenticated, anon or service_role EXECUTE or table-write access to solve this. Before opening Site-save, verify the dedicated roles, the authenticator membership, existing and inherited table/function/default grants, and row visibility under deployed RLS in an authorized isolated environment. The executor requires narrowly reviewed SELECT, INSERT, locking and UPDATE rights on the referenced relations. It must see all Sites that count against an actor's quota. The caller must lack direct table permissions. Verify server credential expiry, rotation and revocation outside the mobile bundle. No credential is generated here.

Two concurrent JavaScript callers and lost-response recovery are tested against PGlite, which queues transactions on one connection. Before release use independent PostgreSQL connections, include a lock wait and a transaction abort, verify exactly one receipt and Site, and demonstrate shutdown without discarding committed receipts. Check the route on the qualified server-only transport. Leave the ingress POST denied until those conditions pass.
