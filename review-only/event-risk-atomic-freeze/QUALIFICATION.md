# Atomic decision-time freeze — isolated candidate, NOT APPLIED

This package is a narrow PostgreSQL concurrency/rollback qualification for the uninstalled decision-time recipient snapshot. It is not a migration, not the PR #259 authority producer, and not permission to call the PR #260 effect writer. The SQL begins with a deliberate exception before any DDL and has no `COMMIT`; only the disposable test harness strips that guard after first proving it aborts. Neither Development nor Production database was accessed.

## Existing contract and chosen key

PR #259's guarded `observer_event_risk_plan_authority` is unique on `(signal_id,risk_engine_version)` and stores Tenant, Site, camera source, Incident, Risk, decision-time recipients/settings/evidence. PR #260 requires that authority and the existing `pg-jsonb-text-v1` algorithm. The separate `canonical-v1` Node/PostgreSQL fixture and review-only producer seam are not compatible replacements. This candidate therefore models **one** frozen row per `(event_id,engine_version)`—the same signal/engine identity as PR #259—and treats Tenant, Site, Source, Incident and Risk as immutable attributes that must match on every replay. A second Risk ID or Tenant/Site mapping for the same event/engine is a conflict, not a second valid plan. This candidate accepts only `canonical-v1`, in its own private `review_atomic` schema; it does not alter or reinterpret historical `pg-jsonb-text-v1` records.

The single statement `review_atomic.freeze_canonical_v1(jsonb)` validates exact shape and scope, independently recomputes `fingerprint` and `digest` using `review_digest.snapshot_digests_v1`, then inserts `frozen_decision` with `ON CONFLICT DO NOTHING`. A unique primary key arbitrates concurrent calls. If inserted, it writes `mandatory_audit` in the same statement/transaction; an audit exception is uncaught and rolls back the frozen insert. On a conflict, it reads the winning row and its audit, returning `REPLAY_IDENTICAL` only if every immutable scope, provenance reference, payload, digest and audit ID matches. It never updates or overwrites a row. Fixture triggers deny UPDATE/DELETE on the frozen and audit tables. PostgreSQL's [INSERT/ON CONFLICT documentation](https://www.postgresql.org/docs/17/sql-insert.html) describes the unique-index arbitration; actual behavior was tested with two live connections below.

## Measured isolated evidence

`node review-only/event-risk-atomic-freeze/run-isolated-postgres-qa.mjs`: **31 isolated PostgreSQL assertions PASS** against a fresh PostgreSQL 17.6 container with `--network none`, `--read-only`, no host mounts, no published ports and tmpfs-only database, removed on exit. The harness confirms those isolation settings from Docker inspection, proves the SQL guard aborts, then installs the candidate only inside that fixture. It tests first insert, exact replay, one-row/one-audit count, algorithm downgrade/unknown version, Tenant/Site/scope conflicts, altered settings with old or recomputed digest, forged hashes, changed ownership/settings provenance, changed audit ID, duplicate event with another Risk, untrusted role denied EXECUTE, and mutation denied. A fixture-only audit trigger deliberately throws **after** the frozen insert; both row and audit remain absent and the key is retryable. Two independent PostgreSQL sessions race for an identical key while the first holds its transaction open: the second waits and returns `REPLAY_IDENTICAL`, leaving one row and one audit. A second two-session race with conflicting settings rejects the loser, again leaving one row and one audit. These are synthetic database behavior tests, not production race/durability proof.

## Hard boundaries and missing facts

- **No verified authority producer or caller.** The function accepts any structurally valid, correctly hashed JSON from a role with INSERT/EXECUTE. Hashes are not signatures or authority. This package grants no live role access. A real deployment needs a server-only identity, independently verified Model A ownership, persisted Risk, versioned recipient/settings read, and a transactionally consistent handoff; the review-only Node seam merely specifies that boundary.
- **Not the full PR #259 plan.** Its proposed authority includes evidence references, watch-rule IDs, expected fingerprints and other decision obligations not represented in this deliberately small freeze fixture. It must not be swapped into PR #259/#260. The real mandatory audit target is `public.immutable_audit_events`, not the fixture audit table. Its immutable writer, ACL and any existing audit writers need separate qualification.
- **Algorithm migration is blocked.** PR #259/#260 hard-code `pg-jsonb-text-v1`; this fixture uses `canonical-v1`. A versioned producer/reader, schema migration, old-record preservation and rollback strategy need coordinated review. No in-place algorithm substitution or downgrade is safe.
- **Raw JSON duplicate object keys** are lost by `JSON.parse`/`jsonb`; a future raw-input boundary must reject them before conversion. The fixture uses trusted typed synthetic values only.
- **Costs, retention, privacy and rollback:** the business need is one bounded snapshot/audit per event/engine for recoverable decisions. Owner is the proposed server-side Risk/effect workflow. Sensitivity is tenant/site/recipient reference metadata, not media. Expected volume is one frozen row plus one audit per distinct event/engine; the PK is the replay lookup. No live usage/cost or legally approved retention is established. Do not deploy or purge records without the actual retention and recovery review. Before activation, rollback may discard an empty candidate; after any real processing, lossless rollback must preserve frozen rows and audit, not drop them.

No database, service, route, Guard, ACL, provider, remote branch or PR was changed. The [Supabase Data API grant change](https://supabase.com/changelog/45329-breaking-change-tables-not-exposed-to-data-and-graphql-api-automatically) reinforces that exposure must be reviewed separately; the fixture grants nothing to `anon`, `authenticated`, or `service_role`.
