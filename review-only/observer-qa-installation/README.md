### Staging and origin review

The mounted POST returns 404 before session access. Its server-side reader is deliberately unwired. The previous per-window environment input has been removed. The remaining deployment flag can only disable or permit checking a separately supplied trusted reader. Changing a Vercel environment variable requires a new deployment to take effect. A five-minute window cannot depend on that process. [Vercel environment variable management](https://vercel.com/docs/environment-variables/managing-environment-variables)

The existing q669-qualified private PostgreSQL window contains the ticket digest, identity, scope and deadline. Its Data API exclusion and ACLs protect that row. The RPC requires the ticket on entry and returns a nonce only after authorization. It cannot provide the plaintext ticket to a Preview process. Exposing its private table, using a general service role or sending a ticket through the app would defeat the qualified boundary. The operator-authorized staged row, precise actor/Site/source and independent SPKI pin remain mandatory.

The existing first-party QA proxy admits an owner to a temporary window, strips its admission cookie and forwards Product cookies to a loopback-only Next process. The proxy rejects a remote upstream for Observer QA. Its single-use code, signed-in Product session and prior physical login do not establish an authenticated secret channel into Vercel or prove that Vercel SSO, Host/HTTPS forwarding and Secure/HttpOnly cookies work together for this endpoint. Gateway credential sync belongs to Home services and is outside this trust domain.

For a future GO, identify and independently attest a backend-only identity and transport that can retrieve **only one** operator-staged window for the intended QA deployment while it is running. Prove that opening and revoking that window take effect across requests on the same deployment, that the ticket stays outside client input, output and logs, and that the actual ingress retains the owner admission and Product session. The reader contract has no request arguments and obtains a fresh value on each call. Only the test harness injects a reader. No staging system or permission was provisioned.

The server independently verifies the Product session, scope, signature and one-use decision. Its reply remains PENDING and grants no viewing permission. The QA-only native signing method reads the existing installation tag and key, compares SPKI and signs the domain-separated nonce. It cannot create or replace a missing key. No WebView bridge or UI invokes it in this candidate. Before physical qualification, separately review the exact main-frame origin and native request/return binding and confirm the installed app has retained the matching installation key. Device possession and hosted association are open.

## Rollout decision

NO GO for hosted staging, deployment or device qualification.** The hosted catalog, ownership, private ticket handoff, ingress restrictions, cookie renewal, native bridge and owner-authorized test window are outstanding. Source merging cannot satisfy them. The isolated PostgreSQL and physical login receipts stand; this integration did not repeat those checks.

If separately approved, first compare the target catalog, roles, grants, RLS and Data API configuration with the q669 receipt. Apply the independently reviewed enrollment forward transaction only to an isolated QA project, verify its pinned issuer and permission surface, then stage a single server-selected window. Keep the route closed until origin, SSO and authenticated app session have been qualified together. Retain the Site SQL as a distinct guarded dependency; no Site creation is part of this rollout. The SQL source guards deliberately abort direct execution.

Rollback closes the flag and edge admission first, revokes the window, removes its server ticket, and uses the independently reviewed enrollment rollback to remove the routine and executor privileges while retaining receipts. Restore the previous app build and proxy if deployed. For a separately activated q669 Site writer, disable its caller, revert its scoped policies with writer-policies-rollback.sql and preserve Sites, receipts and audit rows.
