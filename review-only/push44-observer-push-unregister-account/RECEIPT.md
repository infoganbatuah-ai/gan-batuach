# Observer QA native Push logout account boundary

2026-11-17. Isolated external-drive worktree based on local `integration/development` `72edd07346e939fefe979fc0a4f6198e83ecf1b8`, without fetch. The existing `/api/auth/logout` already revokes an exact current-device row for the server-authenticated user before sign-out, fails closed on revocation error, and rejects unauthenticated requests. `/api/push/unregister` likewise uses the authenticated profile and an exact token or unambiguous device selector; no proof of cross-account DB write was found. Ordinary Management logout is unaffected.

The independent gap is a delayed Observer logout prepared under account A after the browser cookie has changed to B: the old request carried only `observer_push_device_id`. The server could then revoke B's row if B happened to use the same device ID and sign B out, while A's token would remain active. The updated native client includes its locally remembered owner profile as `expected_profile_id` when it has a current Push device. The logout route compares that optional value with the freshly authenticated server user **before** revocation or sign-out and returns 403 on mismatch. This is an honest-client account-consistency fence, not a cryptographic product/device identity. Existing clients without the field remain compatible and are not covered by this new check; full cross-product token isolation still requires trusted binding.
