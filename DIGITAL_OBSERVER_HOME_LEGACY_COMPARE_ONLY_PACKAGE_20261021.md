## Executable core and trust boundary

`services/video-gateway/home-legacy-match-service.mjs` is an **unwired host-local coordinator**, not an HTTP route. It accepts only the two device IDs and a UUID request ID. Its trusted adapter must supply an existing `platform_admin` identity, an explicit purpose/device/Site/tenant approval issued for at most five minutes, an authoritative revocation check, an atomic two-attempt ceiling with one-time request IDs, an independently approved exact enrollment binding, a two-row-scoped verifier reader, a protected local credential reader, and an append-only redacted audit sink. The coordinator audits authorization before either secret read, rechecks expiry/revocation before and after reads, then audits the result. Any missing dependency, denied approval, replay, malformed row, revoked enrollment, expired window, or audit failure returns `UNKNOWN`. Only the trusted adapter may be passed as dependencies; untrusted request input may not supply these callbacks.

The comparator follows the currently deployed Legacy `refresh` verifier semantics: SHA-256 of the UTF-8 credential, compared with the 32-byte stored verifier using a constant-time primitive. The **comparison** is read-only; the existing `refresh` endpoint is not, because it rotates `refresh_token_hash`. It must never be called as a probe. No digest of the local token may be sent as a substitute: under this scheme the digest is verifier-equivalent. The local token and Production verifier may coexist only transiently inside an approved, protected host-local process and may not appear in an HTTP response, audit record, log, Git artifact, or untrusted service. The current project has **not** approved or provided that complete adapter.
