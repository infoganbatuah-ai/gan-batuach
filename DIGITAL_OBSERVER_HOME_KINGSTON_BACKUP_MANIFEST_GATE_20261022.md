## Required exact manifest and snapshot method

Before any approval to upload, produce an owner-only encrypted, file-level manifest from a coordinated source cutoff. Each selected item needs source path (restricted manifest only), type/symlink target, logical and allocated lengths, SHA-256 of captured bytes, sensitivity, classification, capture time, consistency group, independently verified recovery source if excluded, and restore destination. Hash the **captured immutable copies** and verify source stability before/after capture; a hash of a changing live file is not a reliable backup checksum. Deduplication may remove only proven byte-identical copies after retention/provenance review. Keep the manifest and private names outside Git; commit only a redacted total and digest of the encrypted manifest. The previously recorded 36-file Home protected archive hash is historical integrity evidence, not a fresh hash of this full proposed backup.

The isolated `gbi` Colima profile was **not running** at inspection, so current Postgres/Auth state, private Storage object count/bytes and the size of a consistent logical dump are **UNKNOWN**. A VM disk image must not be called a live-safe DB snapshot. At the later authorized backup window: confirm exact local Development stack and DB version; quiesce Development writers only; capture transaction-consistent logical Postgres schema/data including `auth`, `storage` metadata and migration history; record roles/extensions/configuration without exporting secrets; separately capture Storage **object bytes** and bucket policy/config at the same cutoff. Verify dump checksums, table counts, Auth representative records, migration history and tenant RLS in an isolated compatible restore. Supabase explicitly notes database backups contain Storage metadata, not Storage object bytes: <https://supabase.com/docs/guides/platform/backups>. No DB or Storage snapshot was taken here.

Keep ignored local configuration and any protected QA/recovery artifacts in a separately access-controlled, client-encrypted selection after a privacy and Production-secret classification. Do not sweep `.env` trees or Codex sessions blindly; do not export macOS Keychain secrets. `node_modules`, `.next`, Xcode DerivedData, npm caches and application installers are **rebuildable/exclusion candidates**, but a locked rebuild, provenance check or verified independent installer source is still required before their omission is final. The same applies to apparent duplicate signed packages and historical archives. No cache, package or archive was deleted.
