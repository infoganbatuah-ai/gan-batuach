## Decision and measured topology

The existing Kingston physical device is `disk4`, with APFS physical store `disk4s2`, container `disk5`, and one observed volume `disk5s1` named `DIGITAL_OBSERVER`. The existing volume UUID is `D5D524FA-1545-43EE-AC1B-9771D2A7D526`; it is encrypted and writable but `GlobalPermissionsEnabled: false` and mounted `noowners`. Container capacity is 2,048,198,492,160 bytes, with approximately 1,720,429,772,800 bytes free and 327,464,423,424 bytes currently in use. `SMARTStatus` is `Not Supported`; free space is not a health certificate. These values were read from `diskutil` and must be rechecked before any future change.

Apple documents adding an independently formatted APFS (Encrypted) volume to an existing container without repartitioning, with optional reserve and quota; sibling volumes share container free space. The local `diskutil(8)` manual describes `enableOwnership device` as a **per-volume**, host-persistent volume-database setting. A new volume would have a different UUID and can be set to enforce ownership without changing `DIGITAL_OBSERVER`'s `noowners` setting. This is a supported design inference, **not an on-this-drive qualification**: the previous synthetic APFS image could not be mounted in the task environment, and no new volume is authorized yet. The sibling volume would share the **same physical drive and APFS container failure domain**; it is not an independent backup or a cure for the existing disk warnings.

Sources: [Apple APFS volume and size options](https://support.apple.com/guide/disk-utility/add-delete-or-erase-apfs-volumes-dskua9e6a110/mac), [Apple APFS formats/encryption and shared space](https://support.apple.com/en-ie/guide/disk-utility/dsku19ed921c/mac), local `man diskutil` ownership section.

4. Verify archive checksums and perform an **isolated restore on another destination**: representative Git worktree SHA/dirty-file comparison; Development DB startup, representative rows and tenant/RLS checks; Storage object access; package signature/hash verification; configuration permissions; measured RPO/RTO. A second volume shares the same disk, and deleting a mistaken volume permanently removes its data. Rollback of a *new empty* volume is removal only after proving its exact UUID and no unique data; rollback of container corruption requires the independent backup, not an APFS sibling or snapshot.
