
## Backend safety and current limitation

No Production environment files are copied. Standard Next .env files in this worktree are rejected to prevent automatic loading. The launcher drops inherited provider credentials/live flags and accepts only local Supabase URL, publishable key and optional local service-role key from ignored `config/integration.local.env`. Use credentials generated by the isolated local Supabase instance, never Production credentials. Only explicit HTTP loopback IPs are permitted, and local Auth health must respond before full-mode startup. Do not use a tunnel/proxy to Production behind that address.

On 2026-09-19 no Docker runtime or local Supabase configuration was found. **Full backend Product verification and local migration application are blocked until an isolated stack is available.** No production SQL was executed. A healthy Auth service is not proof that schema, RLS or fixtures are correct; validate those separately using the migration ledger and role-boundary tests.

For an explicitly limited UI preview, run `npm run dev:integration -- --ui-only`. This loads no backend credentials and labels every page **UI ONLY — backend unavailable; not Production**. Public routes can be inspected; authenticated dashboard, alerts data, management messaging, camera/Connector and real-provider journeys are NOT thereby verified. Do not call this the fully functional cumulative Product.
