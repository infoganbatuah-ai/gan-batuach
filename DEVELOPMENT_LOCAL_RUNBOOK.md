## Isolated database operation

With the external `gbi` VM running, `npm run dev:database:start` starts the guarded local services. Do not rerun the clean bootstrap over an existing database. `development/database/README.md` documents derivation, exact source provenance and excluded Production activation data. The historical chain remains intact; baseline mapping is not original-history replay.

For every new migration: validate and preserve on a remote branch, integrate the exact reviewed file, record its `developmentApproval`/dependencies, then run `node scripts/development/apply-development-migrations.mjs <explicit-filename.sql>` from the canonical integration worktree. It verifies remote integration identity, dependency order and schema fingerprint before applying only to the pinned local database. Record the resulting receipt with `record-development-applications.mjs` on a scoped ledger branch, push/integrate those DEV states, and require `npm run qa:development-drift` PASS before restarting full mode. A pending receipt may briefly block the launcher; never weaken that guard. Production states remain independent and unchanged.

Fixtures keep security triggers enabled and monitoring/physical actions disabled. GB-M29 remains a separate, explicitly held feature; its three migrations are NOT part of this canonical baseline.
