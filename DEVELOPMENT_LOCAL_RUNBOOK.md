## Backend safety and current limitation

Next dev rewrites the two generated `next-env.d.ts` imports from `.next/types` to `.next/dev/types`. The launcher allows only that exact unstaged generated transformation, not arbitrary edits or staged changes. It never resets the file. Thus a running server may show this one generated Git diff; it is not unpreserved Product work.

No Production environment files are copied. Standard Next .env files in this worktree are rejected to prevent automatic loading. The launcher drops inherited provider credentials/live flags and accepts only local Supabase URL, publishable key and optional local service-role key from ignored `config/integration.local.env`. Use credentials generated by the isolated local Supabase instance, never Production credentials. Only explicit HTTP loopback IPs are permitted, and local Auth health must respond before full-mode startup. Do not use a tunnel/proxy to Production behind that address.
