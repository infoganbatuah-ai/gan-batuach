## V7 evidence and attribution

The immutable-in-Git v7 snapshot and hashes remain at `qa-evidence/push-38/v7-frozen-20260913/`. V7 ran 86,400,104 ms and recorded 1,418/1,440 expected checkpoints. This branch does not replace that ledger. V7 had 22 DVR bad checkpoints (18 windows), 77 Tapo bad checkpoints (27 windows), 40 unusable Connector health observations and three >150-second monitor gaps. These are failed samples, not independent physical fault counts.

The ten DVR streams often ended together; v7 recorded 2,012 relay starts, 1,900 input socket errors and zero authentication rejections. The source of the synchronized stream closure (recorder, LAN, host, or transport implementation) **cannot be proven from v7**. Code inspection did confirm an internal amplification path: discovery conditioned reuse of the shared recorder login on an already-progressing relay, and relay startup could renew that login on a non-auth transport failure when all relays were down. Either path could rotate the shared session during a synchronized interruption. The fix reuses matching credentials regardless of relay state and permits automatic session refresh after an explicit 401/403 rejection only. The existing PUSH 38B bounded relay recovery from `cc48ba5945f4bbccdebf8cf44ede3274715a0282` remains intact. Session epochs, rotations/reasons and per-channel relay start/exit/reason telemetry were added to distinguish a session rotation from stream/decoder/host faults during the next observation. This is **not** proof that the physical shared closure has been eliminated.

Tapo's 146 `upstreamFailed` counter increments cluster in the early v7 seq 29–30 interruption; later recurring Tapo windows do not show additional increments, so those 77 failed samples cannot be attributed wholesale to Wi-Fi or RTSP. V7 logs contain `Network is unreachable` without usable per-failure timestamps. Per-source exit reasons, input transport codes, starts/exits and event-loop delay are now exposed, but **recurring Tapo root cause remains unproven**. No external/environmental finding is asserted.

V7 omitted the 40 Connector `/health` response/error details. The precise original failure class is unrecoverable. Code inspection found `/health` doing supervisor observation/recovery-state mutation and potentially starting the ONNX worker. These side effects have been moved off the request path; the endpoint now reports a versioned, timestamped snapshot, with a lightweight side-effect-free `/health/live`. The monitor separately records timeout, connection refusal, HTTP failure, auth failure, malformed/stale payload and liveness outcome. The historical 40 failures cannot retroactively be relabeled as monitor-only.

Existing PUSH 38B relay recovery and monitor policy tests, shared-session and Connector QA, typecheck, canonical lint, domain QA (30/30), security QA (7/7), and the Production build passed locally. The monitor now records scheduled/actual timestamps, drift, total checkpoint-probe duration, each health outcome, session/relay diagnostics and liveness fallback. Gateway and Connector probes plus process inspection run concurrently with bounded timeouts. A delayed, duplicated or missing checkpoint fails coverage. Adaptive quiet-scene policy remains distinct from a failed eligible AI deep probe; no inference-count-only health claim was added.
