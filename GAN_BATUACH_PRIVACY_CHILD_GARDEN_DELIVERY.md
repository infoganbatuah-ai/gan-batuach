## Exact coverage and authority

An Admin can issue a 24-hour, three-read grant for an approved Management access/export request bound to one Child, one Garden and the requesting Parent. The Parent must be active and have a current, verified `child_guardian_links` record with legal authority and profile scope for that Child. The Child must belong to the exact Garden in the request. The request must have explicit, unblocked `children` and `gardens` scope rows, each with count one and Parent export permission. Active legal holds, revoked guardian authority, request status changes, expiry and read exhaustion fail closed. Admin issuance and revocation are idempotent; a revoked, expired or exhausted grant cannot be reissued for the same request.

Each authorized read returns only the current Child full name and birth date and Garden name and city. Access renders JSON; export downloads the same bounded JSON. It is not a complete Child/Garden export. Documents, health, pickup, payments, messages, other Children, media and Digital Observer records are excluded. Existing Management completion rules remain authoritative: this partial delivery does not complete the privacy request. The UI labels the scope explicitly.

The grant table stores IDs, timestamps and a read counter, not a duplicate data snapshot or export blob. A successful issue, revoke or read writes an immutable audit event in the same transaction; audit failure rolls the action back. The API uses the authenticated requester session, never a service key. Responses are private and non-cacheable, with sandbox CSP, no-referrer and nosniff headers. No public storage, external delivery provider or payment capability is introduced.

## Data, retention, recovery and cost

Business need: limited verified access to a Parent's own Child and Garden identity. Owner: Management privacy administrator. Sensitivity: Child personal data and restricted audit metadata. Query pattern: one Admin issue/revoke, at most three requester reads per approved request; one grant row and at most five new audit events for a complete issue/read/revoke lifecycle. The response enforces bounded UTF-8 Child/Garden text before JSON construction. The grant remains as a no-reissue and audit-link record after expiry. Its final legal retention period is **not yet approved**; no deletion or cleanup job is claimed. Recovery relies on the existing isolated Development backup/restore contract and immutable audit chain; Production backup/restore remains a separate release prerequisite.

No paid dependency or new fixed monthly commitment was added (`₪0` fixed delta). The request and audit writes and response egress are bounded but metered supplier usage was not measured. The verified paying-user denominator is zero, so the ₪15 per paying-user ratio is undefined. The project's ₪1,000 prelaunch cap and all-supplier forecast require separate supplier evidence before Production activation.
