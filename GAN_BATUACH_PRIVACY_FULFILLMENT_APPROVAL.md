The highest-impact demonstrated review gap is approval before scope plus non-atomic decision audit: the Admin Server Action updated `privacy_rights_requests` and separately called `writeAuditEvent`, whose helper logs but absorbs an insertion error. A successful status update could therefore be shown without an immutable decision audit event. The prior completion guard protects `completed` but does not establish this approval milestone.

Migration `20261114223000_management_privacy_approval_atomic_audit.sql` adds a Management-only trigger for status changes to `approved`/`rejected`. It requires an authenticated Admin whose identity matches the reviewer and a documented human reason. Approval also requires a persisted calculated scope, refuses active legal holds, and refuses destructive approval with retention conflicts. The trigger appends the decision audit event in the same database transaction; any audit failure rolls back the status update. It records no full reason in immutable metadata, limiting sensitive duplication. The Admin form now requests an actual reason for approval and no longer performs a separate best-effort audit write. Existing request/hold/subject tables and Digital Observer workflow remain unchanged.

Data owner: project privacy Admin. Sensitivity: high. New records: one existing immutable audit event per new Admin decision; existing retention applies. Expected volume is bounded by human requests, not polling. No new table, bucket, provider, paid dependency or fixed monthly fee. Recovery is a reviewed forward migration restoring the prior guard/UI semantics if needed; existing audit records must remain immutable. Production and real personal data are outside scope.
